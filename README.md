# SYMPO STUDIO

**제약 심포지엄 마이크로사이트를 만들고 운영하는 스튜디오.** 운영자가 콘솔에서 행사를 관리하고 에디터에서 아젠다·자료·참여·테마를 편집하면 참가자용 마이크로사이트에 반영된다.

**라이브 데모** — <https://sympo.superjacob.com> · 소개 페이지 [/intro](https://sympo.superjacob.com/intro)

> 제약 심포지엄 마이크로사이트를 **만들고 현장에서 운영하는 일**을 했습니다. 이 프로젝트는 그때 관찰한 문제를 처음부터 다시 설계한 개인 작업입니다.
>
> 등장하는 브랜드·인물·소속기관·의약품·행사장은 **모두 가상**이며, 운영자 리포트의 수치는 샘플입니다.

---

## 문제

연 수십 회 열리는 행사마다 새 마이크로사이트가 필요했고, 매번 같은 일이 반복됐다. 겪은 문제는 **성격이 다른 두 층**이었다.

**1층 — 제작·운영 효율.** 운영에 필요한 정보가 데이터가 아니라 **이미지와 문자열 안에 갇혀 있었다.**

- 브랜드 컬러가 이미지로만 온다 → 눈으로 맞춰 입력했고, 재사용할 프리셋이 없어 회차마다 반복됐다
- 아젠다가 이미지 슬라이드다 → 연자가 바뀌면 이미지를 다시 받아 다시 올리는 **왕복**이 비용이었다
- URL을 돌려쓰면 공유 캐시에 **이전 회차가 미리보기로** 남는다
- 강의자료는 행사가 **시작된 뒤에** 도착한다 — 올리는 곳은 사무실이 아니라 현장이었다
- 참가자 수백 명이 같은 와이파이를 쓴다 — **네트워크가 가장 느린 시점이 참여 기능을 쓰는 시점**이다

**2층 — 참여율. 도구를 바꿔도 풀리지 않았다.** Q&A·설문을 외부 링크에서 제품 안으로 옮겼더니 Q&A는 회차가 쌓이며 올랐지만 **설문은 그대로였다**(참가자 나잇대가 고령이다). 플랫폼을 갈아타도 효과가 없었고, 결국 **현장에서 사람이 안내하는 것**만 통했다.

> **이 프로젝트가 도전하는 지점 — 현장에서 사람이 하던 안내를 UI가 대신할 수 있는가.**

**관찰과 가설은 갈라 둔다.** 위 내용은 직접 겪은 관찰이고(원자료 [`field-experience.md`](llm-wiki/Reference/field-experience.md)), *"운영자가 직접 편집하면 왕복이 사라진다"*와 *"UI 개선이 고령 사용자의 응답률을 올린다"*는 **아직 검증되지 않은 가설**이다.

## 설계 판단

| | Before | After | 왜 |
|---|---|---|---|
| **행사 식별** | 제목 한 문자열 + URL 재사용 | 필드 분해 + **회차별 고유 슬러그** | 공유 캐시가 이전 회차를 물고 있을 수 없다 |
| **아젠다** | 이미지 슬라이드 | 구조화된 세션 레코드 | 받아서 다시 올리는 **왕복이 사라진다** |
| **테마** | 눈으로 맞춘 HEX | 프리셋 → OKLCH 파생 | `{hue, chroma}` 두 값에서 전 팔레트를 유도 |
| **접근성** | 검증 수단 없음 | WCAG 대비비를 **저장 게이트**로 | 색이 읽히는지 확인할 방법 자체가 없었다 |
| **프리뷰** | 별도 구현 | 참가자 화면과 **같은 컴포넌트** | "프리뷰와 실물이 다르다"를 구조적으로 불가능하게 |

마지막이 가장 마음에 드는 결정이다 — 에디터 프리뷰와 참가자 뷰어가 `Microsite` 하나를 공유해 어긋날 방법이 없다.

## 기술

**Next.js 16 (App Router) · React 19 · TypeScript · Cloudflare (Workers + D1 + R2 + Cron)**

- **런타임 의존성 7개.** `culori`(대비비)·`pdf-lib`(수료증)·`pdfjs-dist`(뷰어)는 **전부 클라이언트용**이고 서버엔 어댑터 외에 없다. 적을수록 2년 뒤에도 `npm install`이 그냥 된다
- **원칙: 저장·조회는 서버, 렌더링·생성은 클라이언트** — 무료 티어가 인색한 자원은 저장 공간이 아니라 **CPU 시간**이다. PDF는 브라우저 canvas로 렌더하고 서버는 열어보지 않는다 → [`ADR 0002`](llm-wiki/Decisions/0002-cloudflare-free-tier-stack.md)
- API 20개 라우트. 참가자 경로는 무인증(제품이 그래야 한다), 운영자 경로는 소유권 검사를 지난다
- **배포 자동**(main 머지 → `lint·test·build` 게이트 → Workers). **원격 DB 마이그레이션만 수동** — 배포는 되돌릴 수 있지만 마이그레이션은 아니다

## 알고 있는 한계

**아직 못 푼 것**

- **설문 응답률 가설이 증명되지 않았다.** 설문은 실제로 저장되고 버튼·글자를 키워 문항을 줄였지만, **그건 화면을 만든 것이지 가설을 검증한 것이 아니다** — 증명에는 실사용 데이터가 필요하고 이 데모엔 없다
- **현장 업로드 UI가 없다.** 서버 API는 동작하지만 운영자가 태블릿에서 올릴 화면이 없다

**구현이 미완인 것** — 아젠다·자료 편집이 아직 서버에 안 붙음 · 키비주얼이 `blob:` URL이라 새로고침을 못 넘김 · 대비비 게이트가 이미지 위 텍스트는 검사 안 함 · 컴포넌트 테스트 인프라 없음(단위 테스트 99건은 CI에서 돈다) · 콘솔 카드·아젠다 드래그가 포인터 전용 · 모바일 실기기 확인 미완

**의도적으로 안 하는 것** — 엣지 rate limiting은 **기각했다**. 무료 플랜은 IP 단독 카운팅이라, 걸면 행사장 단일 IP에서 참가자 전원이 차단된다 → [`ADR 0013`](llm-wiki/Decisions/0013-edge-rate-limiting-rejected.md)

> 여기 적힌 것은 전부 [`Next-Tasks.md`](llm-wiki/Next-Tasks.md)에 과제로 등록돼 있고, 현재 상태 한 장 요약은 [`Status.md`](llm-wiki/Summaries/Status.md)에 있다.

## 로컬 실행

```bash
npm install
npm run db:migrate   # 로컬 D1 스키마 (최초 1회 — 없으면 /api/*가 500)
npm run dev          # http://localhost:3000

npm run lint && npm test && npm run build
```

참가자 페이지(`/[slug]`)를 보려면 두 가지가 더 필요하다.

1. 루트에 `.dev.vars`를 만들고 `DOC_URL_SECRET=아무-로컬-전용-문자열` — 없으면 서명 URL 발급이 실패해 참가자 라우트가 전부 500이다
2. **로컬 D1은 비어 있는 게 정상이다**(시드는 자정 Cron에서만 돈다). API로 직접 만든다:
   ```bash
   curl -X POST localhost:3000/api/events -H 'content-type: application/json' \
     -d '{"title":"로컬 확인용","venue":"로컬","date":"2026-09-20"}'
   curl -X PATCH localhost:3000/api/events/<id> -H 'content-type: application/json' \
     -d '{"status":"공개"}'   # 공개 상태여야 /[slug]가 열린다
   ```

**원격 D1 마이그레이션은 배포 전에 손으로** — `npm run db:migrate:remote`
