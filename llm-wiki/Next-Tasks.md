## 열린 과제

### 1. D1 스키마 설계 + 이벤트별 상태 분리
**무엇** — 이벤트·세션·자료·질문·설문응답·이벤트로그 테이블을 D1(SQLite)에 설계하고, `StudioState`에 평평하게 녹아 있는 편집 대상(title/venue/date/sessions/theme…)을 이벤트 단위로 내린다. 현재는 콘솔에서 어떤 카드를 눌러도 `title`/`venue`만 패치되어 같은 아젠다를 편집한다(`ConsoleScreen.tsx:119`).
**왜** — 나머지 다섯 과제가 전부 여기에 얹힌다. **가장 되돌리기 비싼 결정**이라 먼저 해야 하고, 동시에 데모를 클릭해 보는 사람이 가장 먼저 발견할 결함이기도 하다.
**완료 기준** — 서로 다른 이벤트가 각자의 아젠다·테마를 유지. 로컬에서 D1(wrangler dev)으로 이벤트 CRUD 왕복. 마이그레이션 파일이 저장소에 있음. 이번에 하지 않는 것: 배포, 참여 기능.

### 2. Cloudflare 배포 — 살아있는 링크 확보
**무엇** — `@opennextjs/cloudflare` 어댑터로 Workers/Pages 배포, D1·R2 바인딩, GitHub 연동 자동 배포. Pretendard를 `next/font/local`로 자체 호스팅(외부 CDN 의존 제거). 화면 4개를 App Router 라우트로 분리(`/console`, `/events/[id]/edit`, `/[slug]`, `/report`).
**왜** — **링크 없는 완벽한 계획보다 링크 있는 절반이 낫다.** 포트폴리오에서 가장 먼저 읽히는 요소가 살아있는 URL이고, 이후 기능은 여기에 증분 배포하면 된다. 라우트 분리는 데모 링크를 특정 화면으로 공유할 수 있게 해준다.
**완료 기준** — 공개 URL에서 4개 화면이 딥링크로 열림. 외부 네트워크 의존 0. **결제 수단 미등록 상태 확인**. 이번에 하지 않는 것: 커스텀 도메인.

### 3. Q&A — 첫 서버 쓰기 기능
**무엇** — 참가자 화면의 "질문 남기기"를 실제 저장·조회로 구현. 목록 갱신은 3~5초 폴링. **IP당 rate limit과 글자 수 제한을 이 과제에서 함께 넣는다**(나중이 아니라).
**왜** — 가장 쉽고 임팩트가 가장 크다. 방문자가 남긴 것이 실제로 목록에 뜨는 순간이 이 데모의 하이라이트이며, 여기까지만 해도 "실제 작동하는 데모"가 된다.
**완료 기준** — 다른 브라우저에서 남긴 질문이 보임. rate limit 동작 확인. 매일 시드 리셋 Cron 등록. 이번에 하지 않는 것: 좌장 승인 채팅(즉시성이 필요해 폴링으로 부족).

### 4. 설문 등록 + 집계
**무엇** — 2단 설문 응답 수집과 `GROUP BY` 집계. 응답 완료 시 수료증 노출까지.
**왜** — Q&A와 구조가 거의 같아 3번의 코드가 재사용된다. 설문 응답률은 리포트의 핵심 지표라 5번의 입력이기도 하다.
**완료 기준** — 응답이 저장되고 집계 수치가 리포트에 반영. 수료증은 `pdf-lib`로 **클라이언트 생성**(서버 PDF 생성은 무료 티어에서 막힌다). 이번에 하지 않는 것: 이메일 발송 — 다운로드로 대체.

### 5. OPS 구동 — 리포트를 실측으로
**무엇** — 세션별 열람·자료 열람·설문 완료를 이벤트 로그로 적재하고 리포트 화면을 실제 집계로 교체. 현재 `METRICS`/`OPS`는 하드코딩 샘플이다.
**왜** — 3·4에서 데이터가 쌓여야 의미가 생기므로 순서상 여기다. 도구가 스스로를 측정하지 않으면 개선됐는지 알 수 없다는 것이 리포트 층을 넣은 이유다.
**완료 기준** — 실제 방문 데이터로 열람률이 그려짐. **이벤트 로그 30일 보존 후 삭제 Cron 등록**(방치하면 무한 증가). 실측으로 바뀐 지표에서 `샘플 데이터` 배지 제거, 남은 가상 수치는 배지 유지.

### 6. PDF 뷰어
**무엇** — R2에 자료를 두고 서명 URL로 내주며, 렌더링은 **PDF.js 클라이언트**로. 가상 강의자료 PDF 제작 포함.
**왜** — "해시 파일명 대신 표시명을 관리하고 앱 내에서 연다"는 자료 섹션의 주장을 실제로 증명한다. 독립적이라 순서는 자유지만, 가상 PDF 제작이라는 잡일이 붙어 있다.
**완료 기준** — 모바일에서 페이지 이동·확대가 동작(`<iframe>` 방식은 iOS Safari에서 깨져 기각). 서버 CPU 사용 0.

### 7. 대비비 저장 게이트 실장
**무엇** — `lib/theme.ts:40`의 `lum(L) = L³` 근사를 culori 기반 실제 OKLCH→sRGB 변환으로 교체하고, `allPass`가 거짓일 때 "공개하기"를 실제로 차단(`StudioApp.tsx:245`).
**왜** — "대비비 미달 조합은 만들 수 없다"가 이 제품의 핵심 주장인데 지금은 배지만 그리고 저장을 막지 않는다. 보여주려는 것 자체가 구현돼 있지 않다. 백엔드와 무관해 언제든 할 수 있다.
**완료 기준** — 미달 조합에서 공개 버튼 비활성 + 사유 노출. WCAG 수치가 실제 sRGB 변환 기준. Vitest로 프리셋별 대비비 회귀 테스트.
