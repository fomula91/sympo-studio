## 열린 과제

### 1. README 재작성 — 포트폴리오의 본체
**무엇** — create-next-app 기본값인 README를 프로젝트 문서로 교체. 구성: 한 문장 정의 / 문제 정의 / **설계 판단 4~5개(Before → After → 왜)** / **다시 만들면서 바꾼 것**(실무판에 없던 리포트 층 포함) / 기술 선택과 트레이드오프 / 가상 데이터 고지.
**왜** — 채용담당자는 배포 링크 → README → 코드 순으로 시간을 쓴다. 이 프로젝트의 강점은 코드 기교가 아니라 도메인 판단이고, 그것이 드러나는 유일한 자리가 README다. 현재 README는 "next/font로 Geist를 씁니다"라는 사실과 다른 내용까지 담고 있다.
**완료 기준** — 회사명 없이 "실무에서 관찰한 문제를 처음부터 다시 설계한 개인 프로젝트" 프레이밍으로 작성. 리포트 수치가 샘플임이 README와 UI 배지 양쪽에 명시. 이번에 하지 않는 것: 스크린샷/GIF 삽입(배포 후).

### 2. 정적 export + 무료 영구 배포
**무엇** — `next.config.ts`에 `output: 'export'` 적용, 화면 4개를 App Router 정적 라우트로 분리(`/console`, `/events/[id]/edit`, `/[slug]`, `/report`), Cloudflare Pages 또는 GitHub Pages + GitHub Actions로 배포. Pretendard를 `next/font/local`로 자체 호스팅.
**왜** — "오랫동안 무료"의 적은 비용이 아니라 무료 티어 정책 변경과 비활성 pause다(Heroku·Railway·PlanetScale 전례). 런타임 의존성이 0이면 죽을 것이 없다. 라우트 분리는 데모 링크를 특정 화면으로 공유할 수 있게 해준다.
**완료 기준** — 배포 URL에서 4개 화면이 딥링크로 열림. 외부 네트워크 의존 0(폰트 CDN 제거). `npm run build`가 정적 export로 통과.

### 3. 이벤트별 상태 분리 + localStorage 영속화
**무엇** — `StudioState`에 평평하게 녹아 있는 편집 대상(title/venue/date/sessions/theme…)을 이벤트 단위로 분리. 현재는 콘솔에서 어떤 카드를 눌러도 `title`/`venue`만 패치되어 같은 아젠다를 편집한다(`ConsoleScreen.tsx:119`). 함께 localStorage 직렬화로 새로고침 복원.
**왜** — 데모를 클릭해 보는 사람이 가장 먼저 발견할 결함이다. DB를 붙이든 안 붙이든 어차피 필요한 구조다.
**완료 기준** — 서로 다른 이벤트가 각자의 아젠다·테마를 유지. 새로고침 후 편집 내용 복원. 이번에 하지 않는 것: 서버 영속화.

### 4. 대비비 저장 게이트 실장
**무엇** — `lib/theme.ts:40`의 `lum(L) = L³` 근사를 culori 기반 실제 OKLCH→sRGB 변환으로 교체하고, `allPass`가 거짓일 때 "공개하기"를 실제로 차단(`StudioApp.tsx:245`).
**왜** — "대비비 미달 조합은 만들 수 없다"가 이 제품의 핵심 주장인데 지금은 배지만 그리고 저장을 막지 않는다. 보여주려는 것 자체가 구현돼 있지 않다.
**완료 기준** — 미달 조합에서 공개 버튼 비활성 + 사유 노출. WCAG 수치가 실제 sRGB 변환 기준. Vitest로 프리셋별 대비비 회귀 테스트.
