# sympo-studio — 다음 과제

> **형식 계약 (훅이 파싱한다)**: 열린 과제 제목은 `### FE-N. 제목` / `### BE-N. 제목`.
> 코드 repo의 SessionStart 훅이 `### FE-`·`### BE-`로 시작하는 줄만 추출해 세션에 주입한다. 섹션 헤더는 주입되지 않으므로 **제목의 `FE-`/`BE-` 접두사가 유일한 구분자**다.
> 계약은 접두사뿐이라 아래 섹션 제목은 자유롭게 바꿔도 되고, 추출이 0건이면 훅이 형식 오류 문구를 대신 주입한다.
> 새 과제는 `무엇 → 왜 → 완료 기준`으로 추가하고, 종료되면 아래 종료 기록 표로 옮긴 뒤 지운다. 남은 번호를 다시 매기지 않는다.
> 분리 규칙의 근거는 [[0003-next-tasks-fe-be-split]], 작성 규칙 본문은 `CLAUDE.md`의 「Next-Tasks 작성 규칙」.

**FE는 서로 독립**이라 순서 없이 아무거나 착수할 수 있다(단, 대부분 대응하는 BE에 의존한다 — 각 과제의 `무엇`에 명시).
**BE는 번호가 곧 의존 순서**다. 근거는 [[0001-backend-for-working-demo]], [[0002-cloudflare-free-tier-stack]].

지금 당장 서버 없이 착수 가능한 것: **FE-2**, **FE-7**, 그리고 FE-4의 수료증 부분.

## 열린 과제 — 프론트엔드(FE)

### FE-1. 이벤트별 편집 상태 분리
**무엇** — `StudioState`에 평평하게 녹아 있는 편집 대상(title/venue/date/sessions/theme…)을 이벤트 단위로 내린다. 현재는 콘솔에서 어떤 카드를 눌러도 `title`/`venue`만 패치되어 같은 아젠다를 편집한다(`ConsoleScreen.tsx:119`). **BE-1의 스키마 확정 후 착수** — 먼저 고치면 스키마가 정해질 때 두 번 고치게 된다.
**왜** — 데모를 클릭해 보는 사람이 가장 먼저 발견할 결함이다. 카드가 여러 개인데 편집 결과가 하나뿐인 것은 제품의 기본 전제가 깨진 상태다.
**완료 기준** — 서로 다른 이벤트가 각자의 아젠다·테마를 유지. 이벤트 전환 시 편집 중인 내용이 섞이지 않음.

### FE-2. 라우트 분리 + 폰트 자체 호스팅
**무엇** — 화면 4개를 App Router 라우트로 분리(`/console`, `/events/[id]/edit`, `/[slug]`, `/report`). Pretendard를 `next/font/local`로 자체 호스팅해 외부 CDN 의존을 제거한다. **BE 의존 없음 — 로컬에서 완결된다.**
**왜** — 데모 링크를 특정 화면으로 공유할 수 있게 된다. 외부 CDN은 몇 달 뒤 링크가 열렸을 때 죽어 있을 수 있는 유일한 런타임 의존성이다.
**완료 기준** — 4개 화면이 딥링크로 열림. 외부 네트워크 의존 0(네트워크 탭에서 자사 도메인 외 요청 없음). 이번에 하지 않는 것: 커스텀 도메인.

### FE-3. Q&A 화면 연결
**무엇** — 참가자 화면의 "질문 남기기"를 BE-3 API에 연결. 목록 갱신은 3~5초 폴링. 전송 중·실패·rate limit 초과 상태를 화면에 드러낸다. **BE-3 의존.**
**왜** — 방문자가 남긴 것이 실제로 목록에 뜨는 순간이 이 데모의 하이라이트다.
**완료 기준** — 다른 브라우저에서 남긴 질문이 폴링으로 나타남. rate limit 초과 시 사용자가 이유를 알 수 있음(조용히 실패하지 않음).

### FE-4. 설문 UI + 수료증 클라이언트 생성
**무엇** — 2단 설문 응답 폼을 BE-4에 연결하고, 응답 완료 시 수료증을 `pdf-lib`로 **브라우저에서 생성**해 다운로드시킨다. **설문 폼은 BE-4 의존, 수료증 생성은 독립** — 서버 없이 먼저 만들 수 있다.
**왜** — 서버 PDF 생성은 무료 티어에서 가장 확실하게 막히는 작업이라 클라이언트 생성이 전제다([[0002-cloudflare-free-tier-stack]]).
**완료 기준** — 응답이 저장되고 수료증 PDF가 브라우저에서 생성·다운로드됨. 이번에 하지 않는 것: 이메일 발송 — 다운로드로 대체.

### FE-5. 리포트를 실측 데이터로 교체
**무엇** — `ReportScreen`의 하드코딩 샘플(`METRICS`/`OPS`)을 BE-5의 집계 응답으로 교체한다. **BE-5 의존.**
**왜** — 도구가 스스로를 측정하지 않으면 개선됐는지 알 수 없다는 것이 리포트 층을 넣은 이유다.
**완료 기준** — 실제 방문 데이터로 열람률이 그려짐. 실측으로 바뀐 지표에서 `샘플 데이터` 배지 제거, 남은 가상 수치는 배지 유지(README 고지와 UI 배지가 어긋나지 않을 것).

### FE-6. PDF.js 뷰어 + 가상 강의자료 제작
**무엇** — PDF 렌더링을 **PDF.js 클라이언트**로 구현하고 페이지 이동·확대 UI를 만든다. 데모용 가상 강의자료 PDF 제작 포함. **최종 확인은 BE-6의 서명 URL 의존**이나, 로컬 PDF 파일로 뷰어 개발까지는 먼저 할 수 있다.
**왜** — "해시 파일명 대신 표시명을 관리하고 앱 내에서 연다"는 자료 섹션의 주장을 실제로 증명한다.
**완료 기준** — **모바일에서 페이지 이동·확대가 동작**(`<iframe>` 방식은 iOS Safari에서 깨져 기각). 번들은 lazy load로 초기 로딩에 포함되지 않음.

### FE-7. 대비비 저장 게이트 실장
**무엇** — `lib/theme.ts:40`의 `lum(L) = L³` 근사를 culori 기반 실제 OKLCH→sRGB 변환으로 교체하고, `allPass`가 거짓일 때 "공개하기"를 실제로 차단한다(`StudioApp.tsx:245`). **BE 의존 없음.**
**왜** — "대비비 미달 조합은 만들 수 없다"가 이 제품의 핵심 주장인데 지금은 배지만 그리고 저장을 막지 않는다. **보여주려는 것 자체가 구현돼 있지 않다.**
**완료 기준** — 미달 조합에서 공개 버튼 비활성 + 사유 노출. WCAG 수치가 실제 sRGB 변환 기준. Vitest로 프리셋별 대비비 회귀 테스트.

### FE-10. 스튜디오 셸 브랜드 아이덴티티 적용
**무엇** — 스튜디오 셸(콘솔·에디터·리포트 크롬)에 브랜드 컬러를 입힌다. OKLCH 205도 틸(기존 프리셋 5종의 hue와 겹치지 않는 값)을 `lib/ui.ts`에 `brand`/`brandPress`/`brandSoft` 토큰으로 추가하고, 로고 마크(`components/Logo.tsx`)를 만들어 선택 상태·프라이머리 액션에만 제한적으로 적용한다. 참가자 마이크로사이트에는 이 색이 섞이지 않는다(테넌트 색과 도구 색 분리). **BE 의존 없음.**
**왜** — `lib/ui.ts`가 전부 그레이스케일이라 스튜디오 자체의 정체성이 없었다. 테넌트(행사) 쪽은 이미 프리셋 5종 + `derive()` 파생 시스템이 성숙한데, 정작 도구 자신은 색이 없는 비대칭 상태였다.
**완료 기준** — 셸·콘솔·에디터·리포트 반영 완료(lint·build·헤드리스 스크린샷으로 확인). `huni2/sympo-studio` fork에서 [PR #5](https://github.com/fomula91/sympo-studio/pull/5)로 올라감([[log]] 2026-08-17).

### FE-11. 다크 인트로/소개 페이지
**무엇** — `/intro` 라우트에 다크 톤 소개 페이지를 만든다(헤더·히어로·문제 정의·설계 판단 표·화면 4개·기술 선택·알고 있는 한계·CTA·푸터). 문구는 `docs/problem-redefinition`(PR #2, 미병합)의 정정된 README — field-experience.md로 검증된 두 층 문제 정의를 근거로 쓴다. **FE-10 의존**(브랜드 토큰·로고), BE 의존 없음.
**왜** — README가 이미 갖고 있던 서사를 방문자가 링크를 열고 30초 안에 훑을 수 있는 형태로 옮긴다. 루트가 아직 단일 페이지(FE-2 라우트 분리 전)라 신규 라우트로 뒀다.
**완료 기준** — `/intro`에서 lint·build 통과, 콘솔 에러 0건. 콘솔·에디터·뷰어·리포트 스크린샷 4장(`public/screens/`)이 실제 화면 반영. `design/intro-page` 브랜치(`design/brand-identity` 기반)에서 작업. [PR #6](https://github.com/fomula91/sympo-studio/pull/6)([[log]] 2026-08-17). 이후 라이트 기본 + 다크 토글로 전환됨([[log]] 2026-08-18) — 구조는 유지, 반응형·시각 리듬은 FE-12로 계승.

### FE-12. 소개 페이지 반응형 + 랜딩 재설계
**무엇** — `/intro`를 모바일·태블릿·데스크톱 완전 반응형으로 만들고, README 섹션을 그대로 옮긴 지금의 "문서형" 구성을 랜딩 페이지다운 시각적 리듬으로 다시 짠다. 기준은 [[design]] 6·7절(반응형 구간표, 재설계 원칙). **FE-11 의존**(구조·콘텐츠 재사용), BE 의존 없음.
**왜** — 사용자 피드백: 지금은 1440px 고정이라 폰에서 깨지고, "그냥 여기 프로젝트 PPT 같다"— 표·리스트가 이어지고 스케일 대비·여백 설계가 없다. 채용 담당자가 어떤 기기로 열지 모르는 링크이므로 반응형은 선택이 아니다.
**완료 기준** — 모바일(`<640px`)·태블릿(`640~1023px`)·데스크톱에서 레이아웃 확인(스크린샷 3종). 섹션 최소 하나 이상이 표/리스트가 아닌 다른 시각 레이아웃으로 교체됨. lint·build 통과.
**결과** — grid는 `auto-fit`+`minmax(min(Npx,100%), 1fr)` 패턴으로 미디어쿼리 없이 처리(고정 `minmax(480px,1fr)` 등은 좁은 화면에서 **바닥값이 컨테이너보다 커서 가로 오버플로를 일으킨다는 것**을 375px 실측에서 발견 — `min(Npx,100%)`로 바닥을 캡). 헤더 앵커 내비·"알고 있는 한계" 라벨 줄바꿈처럼 grid로 못 푸는 두 곳만 `globals.css`에 미디어쿼리(`.intro-anchors`, `.intro-limit-row`) 추가. "설계 판단" 7행 표를 Before→After 비교 카드로 교체(표 소거 + 자동 반응형 동시 해결), 결론 인용구를 브랜드 소프트 배경의 큰 텍스트로 격상해 섹션당 "큰 순간" 하나를 만듦. 375/820/1440px 3종 헤드리스 스크린샷, 가로 오버플로 0(재발 방지로 나머지 grid도 방어적으로 `min()` 처리). lint·build 통과.

## 열린 과제 — 백엔드(BE)

### BE-1. D1 스키마 설계 + 이벤트 CRUD
**무엇** — 이벤트·세션·자료·질문·설문응답·이벤트로그 테이블을 D1(SQLite)에 설계하고 마이그레이션 파일을 저장소에 남긴다. 이벤트 CRUD API까지.
**왜** — 나머지 다섯 BE 과제와 FE-1이 전부 여기에 얹힌다. **가장 되돌리기 비싼 결정이라 먼저 해야 한다.**
**완료 기준** — 로컬에서 D1(wrangler dev)으로 이벤트 CRUD 왕복. 마이그레이션 파일이 저장소에 있음. FE 확인 항목: 서로 다른 이벤트가 각자의 아젠다·테마를 반환. 이번에 하지 않는 것: 배포, 참여 기능.

### BE-2. Cloudflare 배포 — 살아있는 링크 확보
**무엇** — `@opennextjs/cloudflare` 어댑터로 Workers/Pages 배포, D1·R2 바인딩, GitHub 연동 자동 배포.
**왜** — **링크 없는 완벽한 계획보다 링크 있는 절반이 낫다.** 포트폴리오에서 가장 먼저 읽히는 요소가 살아있는 URL이고, 이후 기능은 여기에 증분 배포하면 된다.
**완료 기준** — 공개 URL에서 앱이 뜨고 D1·R2 바인딩이 동작. push → 자동 배포. **결제 수단 미등록 상태 확인**(카드가 있으면 봇 트래픽에 청구서가 날아온다). 딥링크 확인은 FE-2 소관.

### BE-3. Q&A 저장·조회 API + 남용 통제
**무엇** — 질문 저장·조회 엔드포인트. **IP당 rate limit과 글자 수 제한을 이 과제에서 함께 넣는다**(나중이 아니라). 매일 시드 리셋 Cron 등록.
**왜** — 가장 쉽고 임팩트가 가장 크다. 여기까지만 해도 "실제 작동하는 데모"가 된다. rate limit을 미루면 봇이 폴링 엔드포인트를 때려 무료 티어 한도 2%가 순식간에 100%가 된다.
**완료 기준** — 저장·조회 왕복. rate limit 동작 확인. 시드 리셋 Cron 등록. 이번에 하지 않는 것: 좌장 승인 채팅(즉시성이 필요해 폴링으로 부족).

### BE-4. 설문 응답 수집 + 집계
**무엇** — 2단 설문 응답 저장과 `GROUP BY` 집계 엔드포인트.
**왜** — BE-3과 구조가 거의 같아 코드가 재사용된다. 설문 응답률은 리포트의 핵심 지표라 BE-5의 입력이기도 하다.
**완료 기준** — 응답이 저장되고 집계 수치가 조회됨. 남용 통제는 BE-3과 동일 정책 적용.

### BE-5. 이벤트 로그 적재 + OPS 집계
**무엇** — 세션별 열람·자료 열람·설문 완료를 이벤트 로그로 적재하고 집계 엔드포인트를 제공한다.
**왜** — BE-3·4에서 데이터가 쌓여야 의미가 생기므로 순서상 여기다.
**완료 기준** — 실제 방문 데이터가 적재되고 집계로 조회됨. **이벤트 로그 30일 보존 후 삭제 Cron 등록**(방치하면 무한 증가한다).

### BE-6. R2 자료 저장 + 서명 URL
**무엇** — 강의자료를 R2에 두고 서명 URL로 내준다. 서버는 URL만 발급하고 렌더링에 관여하지 않는다.
**왜** — 서버 PDF 파싱은 무료 티어에서 막히므로 "저장·조회는 서버, 렌더링은 클라이언트" 원칙을 그대로 적용한다([[0002-cloudflare-free-tier-stack]]). R2는 이그레스가 무료라 전송량 계산이 불필요하다.
**완료 기준** — 서명 URL로 PDF를 받을 수 있고 만료가 동작. **서버 CPU 사용 0**(파싱·변환 없음).
