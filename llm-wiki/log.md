- **[PROJ] GitHub → Discord 웹훅 연동 절차 정리**: 푸시·PR 알림을 Discord 채널에서 받기 위한 설정 절차를 확정. 방식은 **Discord 채널 웹훅 + `/github` 접미사** — Discord 채널 설정 → 연동 → 새 웹후크로 URL을 발급받고, 그 URL 끝에 `/github`를 붙여 GitHub 리포 Settings → Webhooks의 Payload URL로 등록한다. 이 접미사가 GitHub의 push/PR JSON을 Discord가 임베드로 렌더링하게 하는 스위치이며, 빠뜨리면 Discord가 일반 메시지 payload로 해석해 400대 오류를 반환한다(구체 코드는 미검증). 함께 걸리는 함정 둘: **Content type을 `application/json`으로 바꿔야 한다**(GitHub 기본값 `x-www-form-urlencoded`면 실패), **Secret은 비워둔다**(Discord는 GitHub의 `X-Hub-Signature` 검증을 지원하지 않아 넣어도 무의미). 이벤트는 `Send me everything` 대신 개별 선택(Pushes·Pull requests·Issues·Releases, 배포 붙인 뒤엔 Deployment statuses) — 렌더링 못 하는 타입이 섞이면 조용한 실패가 쌓이고 채널도 시끄럽다. 검증은 Recent Deliveries의 응답이 `204`인지로 보되, 등록 직후 오는 `ping`은 Discord가 렌더링하지 않아 채널에 안 뜨므로 **실제 push로 확인**해야 한다. 대안인 Discord GitHub 앱(`/github subscribe`)은 채널별 구독 관리가 편하지만 서버에 봇 추가 + 리포 권한 부여가 필요해 리포 1개에는 과하다고 판단해 채택하지 않음. **repo 코드 변경 없음**이며, 웹훅 URL은 아는 사람이면 누구나 그 채널에 글을 쓸 수 있는 비밀값이라 위키·코드 어디에도 기록하지 않는다(유출 시 Discord에서 웹훅 삭제 후 재발급). 실제 등록·배달 확인은 GitHub·Discord 콘솔에서 수행하는 작업이라 이 로그로는 검증되지 않는다.
