- **[PROJ] 리뷰 계속 — 자료 목록의 "?p" 페이지 수 표시가 사실상 항상 깨져 보임, 작은 파일 크기가 "0.0MB"로 보임(둘 다 fix 후보, 미등록)**: 실제 PDF(`public/demo/sample-lecture.pdf`, 4쪽)를 에디터에 업로드하고 참가자 화면에서 열어 전체 경로를 확인했다. **①** 자료 목록 항목이 "sample-lecture · ?p · 앱 내 열람"으로 뜬다 — `Microsite.tsx`의 `` `${f.pages ?? '?'}p` `` 는 `pages`가 없으면 그대로 물음표를 보여주는데, 업로드 라우트(`app/api/events/[id]/documents/[docId]/upload/route.ts`)의 주석이 "버퍼에 담되 열어 보지는 않는다 — 페이지 수 추출도, 썸네일도, 워터마크도 없다(ADR 0002, 무료 티어는 CPU 시간이 인색한 자원)"이라고 **명시적으로** 적어 뒀다. 즉 `page_count` 컬럼은 설계상 영원히 안 채워지므로, 업로드된 모든 자료가 예외 없이 "?p"로 뜬다 — 희귀 엣지 케이스가 아니라 **이 UI 요소의 유일한 실제 상태**다. 정작 자료를 열면 `PdfViewer.tsx`는 pdf.js로 클라이언트에서 직접 페이지 수를 읽어(`1 / 4` 페이저 정상 동작) 보여주므로, 목록에서만 "?p"를 빼거나 "앱 내 열람"만 남기면 해결된다. **②** 업로드한 1887바이트짜리 파일이 "0.0MB"로 표시된다 — `formatBytes`가 `(bytes/1024/1024).toFixed(1)`이라 소수 둘째 자리 미만은 전부 0.0으로 뭉개져, 작은 자료는 업로드가 비어 보일 수 있다. 테스트로 올린 자료는 확인 후 삭제해 정리했다.
