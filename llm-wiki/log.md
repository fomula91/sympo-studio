## 2026-08-15
- **GitHub → Discord 웹훅 연동 절차 정리**: 푸시·PR 알림을 Discord 채널에서 받기 위한 설정 절차를 확정. 방식은 **Discord 채널 웹훅 + `/github` 접미사** — Discord 채널 설정 → 연동 → 새 웹후크로 URL을 발급받고, 그 URL 끝에 `/github`를 붙여 GitHub 리포 Settings → Webhooks의 Payload URL로 등록한다. 이 접미사가 GitHub의 push/PR JSON을 Discord가 임베드로 렌더링하게 하는 스위치이며, 빠뜨리면 Discord가 일반 메시지 payload로 해석해 400대 오류를 반환한다(구체 코드는 미검증). 함께 걸리는 함정 둘: **Content type을 `application/json`으로 바꿔야 한다**(GitHub 기본값 `x-www-form-urlencoded`면 실패), **Secret은 비워둔다**(Discord는 GitHub의 `X-Hub-Signature` 검증을 지원하지 않아 넣어도 무의미). 이벤트는 `Send me everything` 대신 개별 선택(Pushes·Pull requests·Issues·Releases, 배포 붙인 뒤엔 Deployment statuses) — 렌더링 못 하는 타입이 섞이면 조용한 실패가 쌓이고 채널도 시끄럽다. 검증은 Recent Deliveries의 응답이 `204`인지로 보되, 등록 직후 오는 `ping`은 Discord가 렌더링하지 않아 채널에 안 뜨므로 **실제 push로 확인**해야 한다. 대안인 Discord GitHub 앱(`/github subscribe`)은 채널별 구독 관리가 편하지만 서버에 봇 추가 + 리포 권한 부여가 필요해 리포 1개에는 과하다고 판단해 채택하지 않음. **repo 코드 변경 없음**이며, 웹훅 URL은 아는 사람이면 누구나 그 채널에 글을 쓸 수 있는 비밀값이라 위키·코드 어디에도 기록하지 않는다(유출 시 Discord에서 웹훅 삭제 후 재발급). 실제 등록·배달 확인은 GitHub·Discord 콘솔에서 수행하는 작업이라 이 로그로는 검증되지 않는다.
- **Next-Tasks를 FE/BE로 분리하는 룰 추가 (ADR 0003)**: 열린 과제가 7건으로 늘면서 "브라우저만 열면 되는 일"과 "D1·Workers를 띄워야 하는 일"이 섞여, 세션 시작 시 주입되는 제목만으로는 착수 비용을 가늠할 수 없었다. `## 열린 과제 — 프론트엔드(FE)` / `## 열린 과제 — 백엔드(BE)` 두 섹션 + `FE-N.`/`BE-N.` 제목 접두사로 결정(섹션 분리만으로는 훅이 헤더를 버려 주입 결과에서 구분이 사라지므로 **둘 다** 필요). 훅의 awk(`.claude/settings.json:8`)는 `/^## 열린 과제/{f=1;next}`라 같은 접두사 섹션이 둘이면 양쪽 다 추출되고 `## 종료 기록`에서 멈춘다 — 스크래치패드에서 FE 2건 + BE 1건 + 미끼 항목으로 실측 확인, **훅 수정 불필요**. 가로지르는 과제는 쪼개고 FE 쪽에 BE 의존을 명시, 번호는 각각 독립이며 재번호 금지(로그·ADR 참조가 깨진다). 규칙 본문은 `CLAUDE.md`의 「Next-Tasks 작성 규칙」. 이어서 **`Next-Tasks.md`를 새 룰대로 재편**: 기존 7건 중 가로지르던 5건을 쪼개 **FE 7 + BE 6 = 13건**으로. 순수 FE는 대비비 게이트(FE-7)뿐이었고, 배포·Q&A·설문·OPS·PDF는 전부 가로지르고 있었다. 쪼개면서 **FE↔BE 양방향 의존**이 드러남 — BE-2(배포)의 완료 기준이던 "4개 화면 딥링크"는 실제로 FE-2(라우트 분리)가 해야 하는 일이라 완료 기준을 각 섹션으로 옮겼다. 실제 파일로 훅 awk 재검증: 13건 정상 추출, 종료 기록 표 미포함. **서버 없이 지금 착수 가능한 것은 FE-2·FE-7과 FE-4의 수료증 부분**이며 문서 상단에 명시.
- **SessionStart 훅 파서를 접두사 기준으로 교체 + fail-loud**: FE/BE 분리는 기존 awk로도 동작했지만, 계약이 **섹션 제목이라는 사람이 쓰는 문자열**에 걸려 있어 `## 프론트엔드 과제`처럼 바꾸는 순간 에러 없이 0건이 되는 조용한 실패를 안고 있었다(같은 미끼 파일로 비교 실측 — 기존 0건, 새 방식 정상). 파서를 `awk '/^### (FE|BE)-/{print}'` 한 줄로 교체해 이미 형식 계약인 **제목 접두사**를 직접 읽도록 하고, 추출이 0건이면 형식 오류 안내 문구를 대신 주입하도록 했다. 부수 효과로 섹션 제목이 자유로워지고 종료 기록 아래 `###` 줄은 접두사가 없어 자동 제외된다. 저장 후 `jq -e` 스키마 검증 + settings.json에서 명령을 꺼내 실제 실행해 13건 주입 확인. `CLAUDE.md`·`Next-Tasks.md`·ADR 0003의 형식 계약 서술을 함께 갱신.
