# 프론트엔드 담당자 진입 문서

합류했다면 여기부터. **위키 전체를 읽지 말 것** — 아래 순서대로 필요한 만큼만 본다.

기준일 2026-09-14.

## 1. 5분 요약

제약 심포지엄 마이크로사이트를 만들고 운영하는 스튜디오다. 운영자가 콘솔·에디터에서 편집하면 참가자용 마이크로사이트에 반영된다.

**채용용 포트폴리오**이고 리포지토리 히스토리도 심사 대상이다. 그래서 커밋·문서 규칙이 따로 있다(4절).

지금 상태를 한 장으로 → **[[Summaries/Status]]** · 다음에 뭘 할지 → **[[Summaries/Next]]**

### 지금 가장 중요한 것

**참가자가 보는 쪽은 실제로 동작하고, 운영자가 쓰는 쪽은 아직 목업이다.**

스튜디오 화면 5개는 서버 호출이 **한 줄도 없다**. 열린 FE 과제 중 다섯 개(FE-15·19·23·24·25)가 전부 이 하나의 원인에서 나온다 — 과거에 FE-5·FE-19·FE-23이 모두 착수 중에 이 벽에서 범위를 좁혔다. 그래서 **연결 경로를 정하는 것 자체를 FE-30으로 등록**해 뒀고, 지금의 Next-Task 1번이다.

## 2. 읽는 순서

| 순서 | 문서 | 왜 |
|---|---|---|
| 1 | [[Summaries/Status]] | 지금 무엇이 되고 무엇이 안 되는가 (30초) |
| 2 | [[Summaries/Next]] | **다음에 뭘 할지.** 읽고 바로 착수할 수 있게 (1분) |
| 3 | [[field-experience]] | **문제 정의의 정본.** 무엇을 겪었고 무엇을 안 겪었는가 |
| 4 | [[Next-Tasks]] | **과제 정본.** `FE-`로 시작하는 것이 당신 몫 |
| 5 | [[API-Guide-FE]] | **서버에 붙는 과제를 잡았다면 여기가 정본** |
| 6 | `README.md` | 외부에 보이는 얼굴. 문서를 고칠 때 어긋나지 않게 |

- `Decisions/`(ADR)는 전부 읽지 말고 **과제에 링크로 걸린 것만** 그때 본다.
- 무슨 일이 있었는지 궁금하면 [[Summaries/History]]. 원문 로그는 [[log]].
- 서버 응답의 `error` 문구는 **화면에 그대로 노출해도 되게** 작성돼 있다. 별도 매핑을 만들지 말 것.

## 3. 지금 착수할 수 있는 것

**무엇을 집을지는 [[Summaries/Next]]가 정리해 둔다** — 여기서는 구조만 설명한다.

과제는 두 층이다.

```
과제 = 앞으로 할 일 전체
└── Next-Task = 먼저 할 것 (핫픽스 · 차단 · 필수)
```

- **Next-Task부터 본다.** 지금은 4건 — FE-30(차단) · FE-26 · FE-28 · BE-29(전부 필수). **BE-29는 배포된 서버의 실제 구멍**이라(업로드에 rate limit 0건) FE 담당이라도 존재는 알고 있어야 한다.
- 나머지는 FE/BE 백로그다. **FE 과제는 서로 독립**이라 순서 없이 아무거나 잡아도 된다.
- **FE-15·19·23·24·25는 FE-30이 풀리기 전에 잡지 말 것** — 같은 벽에 다시 부딪힌다.

첫 과제로 적당한 것(작고 독립적): **FE-26**, **FE-28**, **FE-27**, **FE-29**. 전부 방금 머지된 PDF 뷰어 후속이고 한 파일 안에서 끝난다.

각 과제의 `무엇 → 왜 → 완료 기준`은 [[Next-Tasks]]에. **`왜`를 먼저 읽을 것** — 이 프로젝트는 무엇을 만드는지보다 왜 그렇게 만드는지가 결과물이다.

## 4. 지켜야 할 규칙

### 문제를 서술할 때
**[[field-experience]]에 없는 내용을 "관찰"이나 "실무에서 겪은 일"로 쓰지 않는다.** 기존 README가 정확히 그 방식으로 무너졌다 — 화면에서 역산해 문제를 지어냈고 넷 중 셋이 사실과 달랐다([[0004-problem-redefinition]]). 검증되지 않은 것은 **가설이라고 표기**한다.

### 작업이 끝나면
[[log]]의 **오늘 날짜 섹션**(`## YYYY-MM-DD`)에 기록한다. 형식은 `- **[FE] 제목**: 내용` — **태그를 빠뜨리지 말 것**(`[FE]` 프론트 코드 · `[BE]` 백엔드·인프라 · `[PROJ]` 그 외). 한 항목이 FE와 BE를 모두 건드렸으면 태그 두 개를 붙이지 말고 **항목을 쪼갠다**.

코드를 고쳤는데 오늘 기록이 없으면 Stop 훅이 경고한다. 로그는 코드와 **같은 커밋**에 넣는다.

무엇을 썼는지가 아니라 **왜 그렇게 했고 무엇을 확인했는지**를 쓴다. 제목만 봐도 무슨 일이 있었는지 알 수 있게 — 세션 시작 시 주입되는 건 제목뿐이다.

> 과거 로그는 `Archive/`로 분리돼 있다. `log.md`에는 최근 3개 날짜만 둔다.

### 과제를 추가·종료할 때
`### FE-N. 제목` 형식을 지킨다. **이 접두사가 훅 파싱 계약이다** — 없으면 세션에 주입되지 않는다. 번호는 FE·BE 각각 독립이고, **과제가 끝나도 남은 번호를 다시 매기지 않는다**(로그·ADR 참조가 깨진다).

- **새 과제는 기본적으로 FE/BE 백로그에 넣는다.** 핫픽스(배포된 게 깨짐)·차단(다른 과제를 막음)·필수(드러나는 결함)일 때만 **Next-Task 섹션**으로 올린다 — 전부 급하면 아무것도 급하지 않다.
- 섹션 제목은 **전부 `## 열린 과제`로 시작해야** 훅이 읽는다. 바꾸면 그 섹션이 통째로 주입에서 빠진다.
- 종료된 과제는 [[Archive/Closed-Tasks]]로 옮기고 [[Next-Tasks]]에서 지운다.

### 커밋
- **`Co-Authored-By: Claude` 트레일러를 넣지 않는다.** 히스토리도 심사 대상이다.
- 브랜치를 파고 작업한다. `main` 직접 커밋은 하지 않는다.
- 위키 기록을 코드와 함께 커밋한다.

### 설계 결정을 내렸을 때
되돌리기 비싼 판단은 `Decisions/NNNN-*.md`에 ADR로 남긴다(형식: `Decisions/0000-adr-template.md`). **기각한 대안과 그 이유를 반드시 쓴다** — 그게 ADR의 절반이다.

## 5. 검증

```bash
npm run lint     # TS/TSX를 고쳤으면 최소 이것
npm run test     # vitest 23건
npm run build    # 라우팅·설정까지 건드렸으면 (타입 검사 포함)
npm run dev      # UI 동작은 브라우저로 직접 확인
```

우회 실행(`npx tsc` 단독 등) 대신 npm 스크립트를 쓴다.

실패하면 **원인부터 가른다.**

| 출력 | 분류 | 대응 |
|---|---|---|
| `Type error:` · `✖ N problems` | 코드 | 수정 |
| `command not found` · `Cannot find module` | 환경 | `npm install` |
| `EADDRINUSE` | 환경 | 기존 dev 서버(:3000) 종료 |

**환경 문제를 코드로 고치려 들지 말 것.**

### 로컬에서 참가자 페이지를 띄우려면

두 가지가 필요하다. 안 하면 첫 화면부터 막힌다.

1. **`.dev.vars`에 `DOC_URL_SECRET`** (gitignore됨, 각자 로컬에 생성)
   ```
   DOC_URL_SECRET=아무-로컬-전용-문자열
   ```
   없으면 `lib/r2.ts`가 던져서 참가자 라우트가 전부 **500**이다.

2. **로컬 D1에 이벤트가 있어야 한다.** 시드는 자정 Cron(`worker/index.ts`)에서만 돌아 `next dev`로는 채워지지 않는다 — 비어 있는 게 정상이다. API로 직접 만든다:
   ```bash
   npm run db:migrate
   curl -X POST localhost:3000/api/events -H 'content-type: application/json' \
     -d '{"title":"로컬 확인용","venue":"로컬","date":"2026-09-20"}'
   curl -X PATCH localhost:3000/api/events/<id> -H 'content-type: application/json' \
     -d '{"status":"공개"}'   # 공개 상태여야 /[slug]가 열린다
   ```
   상태는 `초안|검수대기|공개|보관` 4종이다. `진행중`은 상태가 아니라 **날짜에서 파생되는 시점**이라 보내면 400이다([[0009-event-status-axes]]).

자동 테스트는 `lib/`의 순수 함수 3파일뿐이다. 컴포넌트 테스트는 도입했다가 우선순위 판단으로 리젝됐다(FE-22, 번호 결번).

## 6. 알아두면 좋은 것

- **에디터 프리뷰와 참가자 뷰어는 같은 `Microsite` 컴포넌트를 공유한다.** 이 프로젝트에서 가장 마음에 드는 설계 판단이라 README에도 적혀 있다. **프리뷰용 별도 구현을 만들지 말 것.**
- **스타일이 인라인 + OKLCH 리터럴이다.** 디자인 프로토타입 충실도를 우선한 결과이고 hover는 `globals.css` 헬퍼 클래스로 우회한다. 정리 방향(Microsite→CSS 변수, 셸→Tailwind)은 아직 과제로 등록돼 있지 않다.
- **데이터는 전부 가상이다.** 브랜드·인물·기관·의약품·행사장 모두 지어낸 것이며 실존으로 보이는 값을 새로 넣지 않는다. 리포트 수치도 샘플이라 `샘플 데이터` 배지를 유지한다.
- **화면은 게스트/로그인 두 모드를 다룬다.** 비로그인도 전부 조작하고 그 편집은 `localStorage`에 영속한다 — **"저장이 안 된다"와 "편집이 사라진다"는 다르다.** 만져본 결과를 확인할 수 없으면 체험이 성립하지 않기 때문이다. 운영자 화면을 만들 때 **"이 버튼이 게스트에게 어떻게 보이는가"가 항상 검토 항목**이다 → [[0007-sso-and-account-model]].
- **조용한 실패를 만들지 않는다.** 게스트가 서버 기능을 누를 때, 오프라인일 때, rate limit에 걸렸을 때 — 전부 **왜 안 되는지가 화면에 보여야** 한다.
- **서명 URL은 10분 TTL이다.** 페이지 로드 때 받은 URL로 한참 뒤에 자료를 열면 만료돼 있다 — 여는 직전에 다시 받는다(`Microsite.openDocument` 참조).
