Domain=evil.example`은 **쿠키 속성 주입**이 됐다(실측). `serializeCookie`에 `encodeURIComponent`, `readCookie`에 짝이 되는 디코딩을 넣었다. 콜백이 쿠키 값을 재검증 없이 `Location`으로 쓰던 것도 `safeNextPath`를 한 번 더 태우게 했다 — 쿠키를 쓸 수 있는 경로가 생기면 ①이 그대로 다시 열린다. **④ 시드의 고정 id 재삽입이 시한폭탄이었다** — 예전엔 `DELETE FROM events`가 테이블을 비워 `VALUES (1, ...)`가 항상 성공했는데, 이번 PR이 삭제를 `owner_id IS NULL`로 한정하면서 그 보장이 사라졌다. 새 DB에서 첫 이벤트를 로그인 사용자가 만들면 id 1을 차지하고, 삭제는 건너뛰고, 재삽입이 `UNIQUE constraint failed: events.id`로 터진다(실측). **batch가 원자적이라 리셋 전체가 롤백되고, worker가 이어서 부르는 R2 고아 정리 — 그 주석이 스스로 "유일한 상한"이라 부르는 것 — 까지 영영 멈춘다.** 증상이 "리셋이 안 된다"가 아니라 "R2가 계속 찬다"로 나타나는 종류다. 데모 이벤트를 **지웠다 다시 만들지 않고 slug로 찾아 제자리에서 UPDATE**하도록 재작성했고(지웠다 만들면 AUTOINCREMENT가 매일 새 id를 준다), 세션 id 고정도 없앤 뒤 `RETURNING id`로 받아 설문·로그가 그 값을 쓰게 했다. **⑤ 소유권을 가드보다 먼저 배포할 뻔했다** — `owner_id`를 채우기 시작했는데 `PATCH`/`DELETE`에 검사가 없었다. 이 PR 전에는 모든 이벤트가 매일 밤 지워져 무보호의 대가가 최대 하루치였지만, 이제 로그인 사용자 이벤트는 영속하므로 **일시적 구멍이 영구적 데이터 손실로 넓어진다.** BE-13의 범위지만 `assertCanEdit`를 앞당겼다 — 소유자가 없는 데모 이벤트는 지금처럼 열어 두고(게스트 체험이 여기 기댄다), 소유자가 있으면 세션이 일치해야 하며 불일치는 **403이 아니라 404**다(BE-7과 같은 규칙). 실측: 비로그인 PATCH·DELETE → 404이고 제목이 안 바뀜, 데모 PATCH → 200(회귀 없음), 브라우저에서 소유자 PATCH → 200. **⑧ 시드 테스트의 항진명제도 고쳤다** — 두 번째 단언이 첫 단언 뒤에는 절대 매치될 수 없는 형태였다. `owner_id IS NULL` 한정과 **고정 id 재삽입 금지**(④의 회귀 가드)를 검사하도록 다시 썼고, 가짜 D1이 SQL 문자열만 본다는 한계를 파일 주석에 명시했다. 남긴 것: ③(`email_verified` 미검사 + upsert 비원자성)과 ⑥(콜백 catch가 `ApiError`만 접음)은 BE-13에서 인가 경계를 손댈 때 함께. `npm run lint`·`test`(23건)·`build` 통과.

- **[BE] BE-16 + BE-10 — 참가자 경로 공개 상태 게이트 + 질문 모더레이션**: 두 과제가 같은 Q&A 라우트를 건드려 함께 했다. **BE-16**: PR #9 교차 리뷰에서 Codex가 "비공개로 전환한 행사에도 질문을 계속 기록할 수 있다"를 발견했고, 재검증에서 설문 라우트까지 같은 결손임을 확인했던 건이다. 원인은 **engage 토글("이 행사가 참여를 받는가")과 공개 상태("이 행사가 공개인가")를 같은 것으로 취급**한 것 — BE-7만 `PUBLIC_STATUSES`를 갖고 있었고 참가자가 쓰는 다른 경로에는 적용된 적이 없었다. 상수와 판정을 `lib/db.ts`의 `PUBLIC_STATUSES`·`assertPublicEvent`로 승격해 Q&A GET·POST, 설문 POST에 적용하고 **BE-7도 자기 상수를 버리고 공통 것을 쓰게** 했다. 비공개는 없는 이벤트와 **같은 404**(존재 비노출, BE-7 규칙 계승)이고, **상태 게이트를 engage 토글보다 먼저** 둔 것이 요점 — 순서가 반대면 비공개 행사가 "Q&A를 받지 않습니다"(403)로 자기 존재를 알려준다. `survey/summary`는 운영자용이라 예외로 두고(초안에서 시험 응답을 넣어 집계를 확인하는 것이 정상 흐름) 근거를 주석에 남겼다. **BE-10**: 스키마와 목록 쿼리가 처음부터 `status='hidden'`을 전제했는데 **그것을 수행하는 코드가 없어** 부적절한 질문의 제거 경로가 이벤트 전체 삭제나 자정 리셋 대기뿐이었다. `PATCH /api/events/[id]/questions/[qid]`로 숨김/복구 — 지우지 않고 상태만 바꾸는 이유는 되돌릴 수 있어야 하기 때문이다(복구가 안 되면 운영자가 모더레이션 자체를 주저한다). `event_id`를 WHERE에 함께 둬 남의 행사 질문을 id만으로 못 건드린다. **`engage_qa` off 정책을 결정**: 목록 조회는 계속 서빙한다 — 토글은 "새 질문을 받는가"이지 "이미 받은 질문을 감추는가"가 아니고, 행사 중 Q&A를 닫았다고 참가자가 보던 목록이 사라지면 그게 더 이상하다. **두 라우트 모두 아직 인가 검사가 없다**(누구나 호출 가능, BE-13에서 얹는다)는 것을 주석에 명시했다. 로컬 실측: 숨김→목록 0건→복구, 잘못된 status 400, 남의 행사 질문 404, 보관 상태에서 Q&A GET·POST·설문 POST 전부 404, 모더레이션·summary는 200(운영자 예외), 진행중 복귀 후 200, BE-7 회귀(진행중 200·초안 404·없는 slug 404). lint·build 통과. **배포(버전 `e5ee6e11`, Cron 유지) 후 프로덕션 실측 완료**: 숨김→목록 0건→복구, 잘못된 status 400, 보관 전환 시 Q&A GET·POST·설문 POST·공개조회 전부 404, 모더레이션·summary는 200(운영자 예외), 진행중 복귀 후 200, 스모크 이벤트 DELETE 정리. **BE-16·BE-10 종료.** **주의**: BE-16 과제 정의는 아직 미머지 브랜치 `docs/pr9-cross-review`에만 있어, 이 브랜치의 열린 과제 목록에는 없는 채로 종료 기록만 추가했다.
- **[BE] BE-8 — Q&A 폴링 GET 읽기 통제 + POST 왕복 절감**: FE-3이 4초 폴링을 실제로 띄우면서 "폴링이 무료 티어를 소진"이 가설에서 현재 위험이 됐다(PR #9 리뷰). GET에 3층을 넣었다: ① 존재 확인과 목록 조회를 batch로 묶어 **요청당 D1 왕복 1회**, ② `Cache-Control: public, max-age=3` — **읽기 티어를 실제로 줄이는 건 이것뿐이다**(참가자 100명이 4초 폴링하면 같은 URL에 초당 25건이 몰리는데 엣지가 창당 1건만 오리진에 넘긴다), ③ `?since=<createdAt>` 커서와 ETag/304. **`since`와 ETag의 효과를 구분해 기록**: `since`는 D1이 인덱스 범위 끝만 읽게 하지만, ETag는 태그를 계산하려면 어차피 조회해야 해서 **바이트만 아끼고 읽기는 그대로다**. 셋 다 선택이라 기존 클라이언트가 안 깨진다(`since` 없으면 전체 윈도우). POST는 이벤트 조회와 rate limit 판정을 batch로 묶어 왕복 2→1 — 403으로 끝나는 무효 POST도 읽기 1회다. 이를 위해 판정을 `rateLimitStatement`(쿼리만 만듦)와 `evaluateRateLimit`(행을 정책과 대조)으로 갈랐고 `assertRateLimit`은 둘의 합성으로 남겨 설문 라우트는 무수정·동작 불변. `survey/summary`에도 `max-age=5` — 처음엔 "운영자가 열어 보는 화면이라 폴링 대상 아님"으로 캐시를 뺐는데 **그 전제가 틀렸다**(분포 쿼리가 응답 행을 전부 GROUP BY로 훑어 요청 하나가 응답 수에 비례해 읽는다). **닫지 못한 것을 정직하게 남겼다**: 무효 POST는 왕복만 줄었을 뿐 *제한되지 않는다* — 판정이 행을 세는 구조라 한 번도 성공 못 한 클라이언트는 셀 행이 없다. 이 한계와 60초 창 해머링·판정 SELECT 2000행 스캔이 전부 같은 뿌리라 **BE-17**(rate limit을 (키,창) 카운터로 전환할지 ADR로 결정)로 묶어 등록했다. 로컬 실측: 캐시 헤더·ETag 확인, `If-None-Match` → 304 0바이트, `since=마지막` → 0건 / `since=과거` → 3건 / 형식오류 400, 회귀 전부 불변(60초 4건째 429, 토큰 없음 강등 4건째 429, qa off 403, null 본문 400, 없는 이벤트 404), summary `max-age=5`. lint·build 통과. **배포(버전 `4e1d118d`, Cron 유지) 후 프로덕션 실측 완료**: 캐시 헤더·ETag, `If-None-Match` → 304 0바이트, `since=마지막` → 0건, `since` 형식오류 400, 같은 토큰 4연타 429(첫 시도는 토큰을 3개 다르게 써서 201이 나왔는데 이는 버킷이 각각 독립인 정상 동작 — 테스트가 틀렸던 것), summary `max-age=5`, 스모크 이벤트 DELETE 정리. **BE-8 종료.**
