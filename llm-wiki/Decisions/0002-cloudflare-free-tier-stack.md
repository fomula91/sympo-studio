# 0002 — Cloudflare 단일 벤더 + "저장·조회는 서버, 렌더링·생성은 클라이언트"

## 상태
채택

## 맥락

[[0001-backend-for-working-demo]]에서 백엔드를 붙이기로 했다. 무료로 오래 유지되어야 하고, 붙일 기능은 네 가지다 — Q&A, 설문 등록·집계, OPS(운영 지표) 구동, PDF 뷰어.

기능별로 자원 소비 성격이 다르다. 앞의 셋은 텍스트 몇 KB를 넣고 빼는 일이라 무료 티어에서 걸릴 구석이 없지만, **PDF는 처리 방식에 따라 결과가 완전히 갈린다.**

## 결정

**호스팅·DB·스토리지를 Cloudflare 한 벤더로 묶는다.**

| 층 | 선택 |
|---|---|
| 호스팅 + 서버 런타임 | Cloudflare Workers/Pages (`@opennextjs/cloudflare` 어댑터) |
| DB | **D1** (SQLite) |
| 파일 | **R2** (PDF) |
| 실시간 | 폴링 3~5초로 시작 (WebSocket 아님) |
| 자동 리셋·정리 | Cron Triggers |

그리고 아키텍처 원칙 하나를 전 기능에 적용한다.

> **저장·조회는 서버에서, 렌더링·생성은 클라이언트에서.**

구체적으로:
- **PDF 열람** — 서버는 R2 서명 URL만 내주고, 렌더링은 **PDF.js가 브라우저에서** 한다.
- **수료증 발급** — 서버 생성이 아니라 `pdf-lib`로 **클라이언트에서 생성**한다.
- **OPS 집계** — 이벤트 로그를 D1에 적재하고 `GROUP BY`로 조회한다. 사전 집계 테이블은 만들지 않는다(데모 규모에서 불필요).

## 근거

**왜 Cloudflare인가**
- 무료 티어에 **상업적 사용 제한이 없다.** Vercel Hobby는 상업적 사용 금지 조항이 있어, 이 데모가 언젠가 영업 자료로 쓰이면 약관 위반이 된다.
- R2는 **이그레스가 무료**다. PDF 열람은 전송량이 유일한 변수인데 이 항목이 사라진다.
- D1은 비활성 pause가 없다. Supabase 무료 티어는 일정 기간 요청이 없으면 프로젝트를 정지시키는데, 포트폴리오 링크가 몇 달 뒤 열렸을 때 죽어 있는 시나리오가 정확히 이것이다.
- 벤더가 하나라 계정·과금·장애 지점이 분산되지 않는다.

**왜 CPU를 쓰는 작업을 클라이언트로 미는가**
무료 티어가 인색한 자원은 저장 공간도 요청 수도 아니고 **CPU 시간**이다. 견적상 요청 수 ~2%, DB 저장 ~0.1%, R2 저장 ~0.2%로 한도는 문제가 아니었다. 반면 서버 PDF 파싱·생성은 무료 티어에서 가장 확실하게 막히는 작업이다. 이 원칙을 지키면 네 기능이 전부 무료 티어 안에 들어온다.

**왜 iframe이 아니라 PDF.js인가**
`<iframe src="...pdf">`는 무료이고 구현도 없지만, iOS Safari에서 첫 페이지만 보이는 등 모바일 동작이 제각각이다. **참가자의 대부분이 모바일인 제품에서 치명적이다.** PDF.js는 번들이 ~1MB로 크지만 lazy load로 해결되고, 페이지 이동·확대 UI를 직접 만들 수 있어 "앱 내 열람"이라는 제품 주장과도 맞는다.

**왜 폴링인가**
Durable Objects 기반 WebSocket은 무료 티어가 제한적이다. 데모 규모에서 3~5초 폴링과 실시간의 체감 차이는 없다.

**기각한 대안** — Vercel Hobby + Neon + Vercel Cron. Next.js 네이티브라 어댑터 마찰이 없는 것이 큰 장점이지만, 벤더가 둘로 갈리고 상업적 사용 조항을 계속 안고 간다. **Cloudflare는 어댑터 마찰, Vercel은 약관 마찰 — 둘 중 하나는 감수해야 하며 후자가 더 오래 발목을 잡는다고 판단했다.**

## 결과·트레이드오프

**얻는 것** — 네 기능 전부가 한도의 1~2% 안에서 동작한다. 트래픽이 100배 늘어도 무료다. 이그레스 무료 덕에 PDF 전송량 계산이 불필요하다.

**감수하는 것**
- **어댑터 마찰.** `@opennextjs/cloudflare`는 Next.js 네이티브 배포보다 손이 간다. Node 런타임 API 일부가 제약되고, Next.js 메이저 업그레이드 때 어댑터를 기다려야 한다. 이것이 이 결정의 가장 큰 리스크다.
- PDF.js 번들 ~1MB. lazy load로 완화하나 0은 아니다.
- 폴링은 진짜 실시간이 아니다. 좌장 승인 채팅처럼 즉시성이 중요한 기능을 나중에 넣으면 재검토가 필요하다.
- **가상 강의자료 PDF를 직접 제작해야 한다.** 실제 자료를 쓸 수 없으므로 슬라이드 몇 장짜리를 만들어야 하는 잡일이 생긴다.

**함께 반드시 넣을 것 (1일차에, 나중이 아니라)**
- IP당 rate limit — 봇이 폴링 엔드포인트를 때리면 한도 2%가 순식간에 100%가 된다.
- 이벤트 로그 30일 보존 후 삭제 Cron — 방치하면 무한 증가한다.
- **결제 수단 미등록** — 카드가 없으면 최악이 "잠시 차단"이고, 카드가 있으면 봇 트래픽에 청구서가 날아온다.

## 재검토 트리거

- 어댑터가 Next.js 메이저 업그레이드를 6개월 이상 따라오지 못할 때 → Vercel + Neon 조합 재검토.
- 무료 티어 한도의 50%를 넘길 때 → 악용을 의심하고 rate limit부터 점검(정상 트래픽으로 도달할 수 있는 수치가 아니다).
- 즉시성이 필요한 기능(좌장 승인 채팅 등)을 넣을 때 → 폴링 → Durable Objects 전환 검토.
- 무료 티어 수치는 정책이 바뀐다. **착수 직전 Cloudflare 문서로 재확인할 것.**
