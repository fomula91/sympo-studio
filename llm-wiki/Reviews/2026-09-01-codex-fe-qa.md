# Codex 프론트엔드 리뷰 — Q&A 연결

- 검토일: 2026-09-01
- 범위: `components/Microsite.tsx`, `components/QaPanel.tsx`, `lib/api.ts`
- 관점: 참가자 마이크로사이트의 Q&A 흐름, 실제 이벤트 연결, 접근성, 실시간 갱신
- 검증: `npm run lint` 통과

## 결론

Q&A 화면의 기본 흐름(온라인 상태, 입력 길이 제한, 전송 중 상태, 429·403 메시지)은 갖춰졌지만, 현재 구현은 특정 시드 이벤트에 고정돼 있어 참가자 화면에 연결하면 다른 이벤트의 질문을 조회·등록하는 치명적인 문제가 있다. 이 문제를 먼저 고친 뒤 폴링 신뢰성과 키보드 접근성을 보완해야 한다.

## 지적 사항

### P1 — Q&A가 현재 행사와 연결되지 않음

**근거**

- `lib/api.ts`가 `PUBLIC_EVENT_ID = 1`을 정의한다.
- `QaPanel`은 GET·POST 모두 이 상수를 쓴다.
- `Microsite`는 이벤트의 제목·일정·참여 토글을 props로 받아 렌더하지만 이벤트 `id`는 받지 않는다.

**영향**

이벤트 A의 참가자 화면에서 질문을 남겨도 id=1 이벤트에 저장되고, 목록 역시 id=1의 질문을 표시한다. 에디터 프리뷰에서는 더 눈에 띄지 않아 잘못된 데이터가 실제 행사 Q&A에 섞일 수 있다.

**권장 수정**

공개 조회(`GET /api/public/[slug]`) 응답의 `id`를 참가자 페이지의 정본으로 삼는다. 이를 `Microsite` → `QaPanel` prop으로 전달하고 `fetchQuestions(eventId)`·`postQuestion(eventId, body)`에 사용한다. `PUBLIC_EVENT_ID`는 삭제하며, 시드의 id=1은 API 실험에만 쓴다.

### P2 — 폴링 응답이 캐시되어 새 질문이 보이지 않을 수 있음

**근거**

- `QaPanel`은 4초마다 `fetchQuestions`를 호출한다.
- `fetchQuestions`의 `fetch`에 캐시 정책이 명시되지 않았다.

**영향**

참가자에게 실시간으로 보여야 하는 목록이 브라우저 또는 중간 캐시의 응답을 재사용하면 새 질문이 표시되지 않을 수 있다.

**권장 수정**

현재 GET 계약에는 ETag가 없으므로 `fetch(url, { cache: 'no-store' })`를 명시한다. BE-8에서 ETag 또는 `since` 커서 계약이 생기면, 그때 재검증·증분 조회 정책으로 바꾼다. 또한 요청이 4초 이상 걸릴 수 있으므로 이전 요청이 끝난 뒤 다음 폴링을 시작해 중복 요청을 피한다.

### P2 — 입력 패널을 연 뒤 초점과 상태 알림이 없음

**근거**

- `Microsite`에서 "질문 남기기" 버튼은 클릭 즉시 제거되고 `QaPanel`이 렌더된다.
- 새 textarea로 초점을 옮기는 로직이 없다.
- 조회·전송 오류가 일반 `div`로만 출력된다.

**영향**

키보드 또는 스크린리더 사용자는 패널이 열렸다는 것과 오류가 발생했다는 것을 즉시 알기 어렵다.

**권장 수정**

textarea ref를 두고 패널 마운트 시 `focus()`한다. 오류 영역에는 `role="alert"` 또는 `aria-live="polite"`를 둔다. 버튼과 textarea의 터치 대상은 현재 44px 이상이라 유지한다.

### P3 — 성공한 질문이 다음 폴링까지 표시되지 않음

**근거**

- `postQuestion`은 201 응답의 `Question` 객체를 반환한다.
- `QaPanel.handleSubmit`은 이 반환값을 사용하지 않고 입력값만 비운다.

**영향**

질문을 보낸 사용자는 최대 4초 동안 성공 여부를 목록에서 확인하지 못한다. 네트워크가 느린 환경에서는 전송이 반영됐는지 불안해 재전송할 가능성도 있다.

**권장 수정**

성공 응답을 `setQuestions((current) => [...(current ?? []), question])`으로 즉시 추가하거나, POST 성공 직후 목록을 재조회한다. 동일 질문이 다음 폴링에서 중복되지 않도록 id 기준으로 병합한다.

## 구현 순서

1. 이벤트 ID prop 전달과 고정 상수 제거(P1)
2. POST 성공 후 즉시 목록 병합(P3)
3. 캐시·폴링 중복 방지(P2)
4. 초점 이동과 라이브 오류 알림(P2)
