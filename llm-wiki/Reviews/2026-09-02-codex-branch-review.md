# Codex 브랜치 코드 리뷰

- 검토일: 2026-09-02
- 대상 브랜치: `chore/claude-local-role-notes`
- 비교 기준: `main...HEAD`
- 관점: 참가자 Q&A, 스튜디오 미리보기의 데이터 경계, 수료증 PDF UX

## 결론

참가자 공개 페이지는 실제 이벤트 ID를 Q&A에 전달하도록 개선됐지만, 스튜디오의 모바일·태블릿 미리보기는 여전히 시드 이벤트(`id=1`)에 연결된 살아있는 Q&A를 렌더한다. 운영자가 미리보기에서 질문을 등록하면 목업이 아니라 실제 D1 데이터에 저장될 수 있으므로 머지 전에 차단해야 한다.

## 지적 사항

### P1 — 스튜디오 미리보기가 실제 행사 Q&A에 쓰기를 일으킴

**근거**

- `components/screens/ViewerScreen.tsx:26-28`과 `components/screens/EditorScreen.tsx:1148-1150`은 `Microsite`에 `eventId={1}`을 넘긴다.
- `Microsite`는 활성 Q&A일 때 `QaPanel`을 렌더하고, 패널은 이 ID로 GET·POST를 수행한다.

**영향**

운영자가 스튜디오의 "참가자 뷰" 또는 에디터 우측 미리보기에서 질문을 전송하면, 편집 중인 목업 이벤트와 무관하게 D1 시드 행사에 실제 질문이 등록된다. 미리보기의 질문 목록 역시 해당 시드 행사 데이터가 보여 편집 대상과 불일치한다.

**권장 수정**

`Microsite`에 `preview` 또는 `readOnly` prop을 추가해 스튜디오 호출부에서는 Q&A 입력·폴링을 렌더하지 않는다. 실제 참가자 공개 페이지(`/[slug]`)에서만 공개 조회 응답의 이벤트 ID를 전달해 Q&A 요청을 허용한다.

### P2 — 늦게 도착한 폴링 결과가 방금 등록한 질문을 지움

**근거**

- `QaPanel`의 GET 폴링은 응답을 `setQuestions(qs)`로 통째로 대체한다.
- POST 성공은 반환된 질문을 현재 목록에 즉시 append한다.

**재현 순서**

1. 질문 목록 GET이 먼저 시작되고 네트워크 지연으로 응답이 늦어진다.
2. 사용자가 질문을 등록하고 POST가 먼저 201로 완료된다.
3. 성공 응답의 질문이 목록에 append된다.
4. 새 질문을 포함하지 않은 이전 GET 응답이 도착해 목록 전체를 덮어쓴다.

**영향**

새 질문이 다음 폴링 전까지 목록에서 사라진다. "즉시 반영" 동작이 간헐적으로 무효화되고, 사용자는 전송 실패로 오해해 재시도할 수 있다.

**권장 수정**

GET 결과를 기존 목록과 ID 기준으로 병합하거나, POST 성공 시 진행 중인 GET의 결과를 무효화한다. 요청 세대 번호 또는 `AbortController`로 가장 최신 요청만 state를 갱신하게 해도 된다.

### P2 — 긴 문구가 수료증 PDF의 페이지 밖으로 넘침

**근거**

- `lib/certificate.ts`의 `centerX()`는 텍스트 폭이 페이지보다 크면 음수 x 좌표를 반환한다.
- 행사명·참가자명에는 수료증 렌더 전 길이 제한·줄바꿈·축소가 없다.

**영향**

긴 행사명 또는 참가자명을 입력하면 PDF의 이름·행사명 줄이 양옆으로 잘린다. 다운로드 파일명도 행사명을 그대로 사용해 운영체제별로 부적절한 문자나 지나치게 긴 이름이 될 수 있다.

**권장 수정**

각 줄의 최대 폭을 정해 글자 크기를 줄이거나 줄바꿈한다. 다운로드 파일명은 길이를 제한하고 파일 시스템 예약 문자를 제거한다.

## 검증

- `npm run lint` 통과
- `npm run build` 통과
- `npm run test`는 코드 실패가 아니라 현재 실행 환경의 프로세스 생성 권한 오류(`spawn EPERM`)로 시작되지 못했다.
