# SYMPO STUDIO — 디자인 컨셉

이 문서는 지금까지 구현된 디자인 결정을 근거와 함께 정리한 것이다. 새로 화면을 만들거나 기존 화면을 고칠 때 참조하는 정본이다. 코드가 근거이므로, 코드가 바뀌면 이 문서도 같이 고친다.

## 0. 세 화면, 세 개의 다른 제품

이 앱은 겉보기엔 하나지만 실제로는 성격이 다른 세 화면을 담고 있고, **디자인 결정은 화면마다 다르게 내린다.**

| 화면 | 정체 | 보는 사람 | 기기 |
|---|---|---|---|
| **스튜디오 셸** (콘솔·에디터·리포트) | 운영자용 데스크톱 도구 | 운영자 | 데스크톱 |
| **참가자 마이크로사이트** (`Microsite.tsx`) | 행사 참가자용 제품 | 참가자 | 모바일·태블릿 |
| **소개 페이지** (`/intro`) | 포트폴리오 랜딩 | 채용 담당자 | 아무 기기나 (링크를 열자마자 판단) |

이 구분을 잊으면 세 화면을 같은 규칙으로 억지로 맞추게 되고, 그 결과가 지금 `/intro`가 겪고 있는 문제다 — 아래 6·7절 참조.

## 1. 색 — 두 개의 분리된 시스템

**"도구의 색"과 "행사의 색"은 절대 섞이지 않는다.** 이게 이 프로젝트에서 가장 중요한 색 규칙이다.

### 1-1. 도구 색 (스튜디오 셸 + 소개 페이지)

`lib/ui.ts`의 `UI` 토큰. 값은 전부 `app/globals.css`의 CSS 변수를 가리키고, 실제 색은 `:root`(라이트)와 `:root[data-theme='dark']`(다크)에 정의돼 있다.

| 토큰 | 라이트 | 다크 | 용도 |
|---|---|---|---|
| `brand` | `oklch(0.475 0.11 205)` | `oklch(0.72 0.1 205)` | 선택 상태 · 프라이머리 액션 |
| `brandPress` | `oklch(0.31 0.075 205)` | `oklch(0.6 0.11 205)` | 브랜드 버튼 hover |
| `brandSoft` | `oklch(0.955 0.016 205)` | `oklch(0.28 0.032 205)` | 선택 행 배경 |
| `onBrand` | `#fff` | `oklch(0.15 0.02 205)` | 브랜드 배경 위 텍스트 |
| `ink` / `ink2` | 0.22 / 0.3 (hue 250) | 0.96 / 0.86 | 본문 / 보조 강조 텍스트 |
| `muted` / `muted2` | 0.55 / 0.45 | 0.68 / 0.62 | 2차 텍스트 |
| `faint` | 0.62 | 0.58 | 3차 텍스트·캡션 |
| `bg` / `surface` | 0.968 / `#fff` | 0.19 / 0.245 | 앱 배경 / 카드 배경 |
| `line` / `lineFaint` | 0.912 / 0.945 | 0.33 / 0.28 | 테두리 |
| `green` | `oklch(0.55 0.11 145)` | `oklch(0.68 0.13 145)` | 저장됨 표시 (상태 배지와는 별개) |

hue **205**를 브랜드로 쓴 이유: 테넌트 프리셋 5종(72/158/252/305/255)이 비워둔 유일한 구간이라서다. 관리자 화면에서 "이건 도구의 색이다"가 프리셋과 겹치지 않아 시각적으로도 구분된다.

**brand는 화면 면적의 5% 미만으로 쓴다.** 선택된 내비 항목, 프라이머리 버튼, 선택된 카드의 테두리·링 — 여기까지다. 배경 전체나 큰 블록에 칠하지 않는다.

### 1-2. 행사 색 (참가자 마이크로사이트)

`lib/theme.ts`의 `derive(preset, mode)`. 프리셋은 `{hue, chroma}` 두 값뿐이고, 여기서 `bg/surface/line/ink/muted/brand/onBrand/soft` 전체를 라이트/다크 각각 파생한다 (`lib/data.ts`의 `PRESETS`).

| 프리셋 | hue | chroma |
|---|---|---|
| 슬레이트 뉴트럴 | 255 | 0.028 |
| AURORA 그린 | 158 | 0.105 |
| PRIME 블루 | 252 | 0.125 |
| VERTEX 퍼플 | 305 | 0.115 |
| HERO 앰버 | 72 | 0.115 |

파생된 조합은 `contrastRows()`로 WCAG AA 대비비를 검증한다(FE-7에서 저장 게이트로 강제 예정, 현재는 배지만).

### 1-3. 왜 분리하는가

`Microsite.tsx`는 `UI`를 **import하지 않는다.** 참가자가 보는 화면의 색은 100% `theme` prop(그 행사의 프리셋에서 파생된 값)에서만 온다. 도구가 다크모드로 바뀌어도 참가자 화면은 전혀 영향받지 않는다 — 실제로 에디터에서 셸을 다크로 바꿔도 라이브 프리뷰 안의 AURORA 그린은 그대로인 것으로 확인했다. 이 분리가 깨지는 순간 "행사마다 색이 다르다"는 제품의 핵심 주장이 무너진다.

## 2. 라이트 · 다크

- **기본은 라이트.** `<html data-theme="dark">`가 있을 때만 다크. `components/ThemeToggle.tsx`가 토글하고 `localStorage`(`sympo-theme`)에 남긴다.
- 깜빡임 방지: `app/layout.tsx`의 페인트 전 인라인 스크립트가 저장된 값을 읽어 `<html>`에 미리 반영한다. 이 때문에 서버 렌더와 다를 수 있어 `<html suppressHydrationWarning>`을 명시했다.
- **셸 + 소개 페이지는 하나의 다크모드를 공유한다.** 두 화면 다 `UI` 토큰을 쓰기 때문에 토글 하나로 같이 바뀐다.
- **마이크로사이트는 독립된 라이트/다크가 있다** — 에디터의 "02 · 표면" 세그먼트로 행사마다 따로 고른다. 셸의 다크모드 토글과는 무관하다. 이것도 1-3의 분리 원칙과 같은 이유다.
- **알려진 갭** — 상태 배지(`pillStyle`), 대비비 통과/미달 배지, 리포트 증감 배지는 의미색(초록/주황/빨강)이라 이번 다크모드 작업에서 그대로 뒀다. 다크에서도 읽히지만 배경이 살짝 밝게 뜬다. 손대려면 각 배지 로직에 다크 페어를 추가해야 한다.

## 3. 타이포그래피

- 서체는 Pretendard(`app/layout.tsx`에서 CDN 로드 — 정리 과제로 `next/font/local` 자체 호스팅 전환이 FE-2에 있음).
- 기계가 생성한 값(슬러그·날짜코드·시각·대비비 수치·지표)만 모노스페이스(`MONO`, `lib/ui.ts`). 사람이 쓰는 글은 전부 Pretendard.
- 굵기 위계: 750 화면 타이틀/히어로 · 700 카드 제목/섹션 헤딩 · 650 버튼/라벨 · 400 본문.
- letter-spacing은 글자가 클수록 좁게: 큰 헤드라인 `-0.03~-0.045em`, 본문은 `-0.01~-0.02em`.

## 4. 로고

`components/Logo.tsx`. 라운드 사각형(브랜드색) 안에 같은 크기의 라운드 사각형 두 개가 우하향으로 어긋나게 겹친 형태 — 뒤는 흰 외곽선만, 앞은 흰색으로 채움. 이미지 파일 없이 div 3개로 만든다(`LogoMark`), 워드마크 락업은 `LogoLockup`.

의미: 에디터의 라이브 프리뷰와 참가자 뷰어가 같은 `Microsite` 컴포넌트를 공유해서 어긋날 수 없다는 것 — 1-3에서 설명한 원칙을 형태로 옮긴 것이다.

`LogoLockup`은 `ink`/`sub` 색을 props로 받는다 — 다크 배경(소개 페이지 다크모드 등)에서 라이트 셸 색을 그대로 쓰면 안 보이는 버그가 있었고, 지금은 기본값이 `UI.ink`/`UI.brand`라 테마를 따라간다.

## 5. 레이아웃 · 간격 · 반경

- 페이지 패딩은 24px 기준(`padding: '24px 24px 80~120px'`), 하단은 플로팅 요소(선택 바 등)를 위해 더 준다.
- `maxWidth`는 화면 성격에 따라 다르다: 콘솔 1400 · 소개 페이지 1120 · 폼 성격의 섹션(기본 정보 등) 600 · 리스트 성격 640~660.
- 라운드 반경은 7~16px 대역에서 요소 크기에 비례: 작은 배지 6~7 · 버튼 9~11 · 카드 12~16.
- 카드 = `surface` 배경 + `line` 1px 테두리 + radius 12~16. 선택된 카드는 `brand` 테두리 + `0 0 0 3px oklch(0.475 0.11 205 / 0.09)` 링.
- 클릭 대상 최소 높이 44px(터치 타깃).

## 6. 반응형 — 화면마다 다른 전략

**"반응형이어야 한다"는 요구는 세 화면에 똑같이 적용되지 않는다.**

| 화면 | 전략 | 근거 | 현재 상태 |
|---|---|---|---|
| 스튜디오 셸 | **데스크톱 전용.** 모바일 대응 안 함 | 운영자가 현장 세팅 전에 미리 준비하는 도구다. Figma·Linear·Notion류 어드민 도구와 같은 범주 — 참가자 화면의 모바일 검증은 뷰어 화면이 데스크톱 안에서 대신한다 | 의도된 설계. `minWidth: 640` 등 데스크톱 전제 |
| 참가자 마이크로사이트 | **모바일·태블릿 퍼스트** | 실제 사용 기기가 참가자 폰과 현장 태블릿이다(`field-experience.md`) | 뷰어·프리뷰의 **고정 프레임**(390/834px) 안에서만 검증됨. 실제 배포 시 뷰포트에 맞춘 fluid 폭 대응은 미검증 — 알려진 갭 |
| 소개 페이지 | **완전 반응형 필요** | 채용 담당자가 어떤 기기로 링크를 열지 알 수 없다. 30초 판단이 이 프로젝트의 전제 조건이다(README) | **지금 안 됨.** 1440px 고정 레이아웃, 다음 과제로 처리 |

### 소개 페이지 반응형 — 적용할 기준

| 구간 | 폭 | 처리 |
|---|---|---|
| 모바일 | `<640px` | 1열, 히어로 폰트 축소(52→32px 대역), 헤더 앵커 내비 숨김(로고+토글+CTA만), 설계 판단 표는 가로 스크롤 유지, 화면 그리드 1열 |
| 태블릿 | `640~1023px` | 2열 그리드 유지, 히어로 폰트 중간값 |
| 데스크톱 | `≥1024px` | 지금 레이아웃 |

## 7. 소개 페이지가 다시 풀어야 할 문제 — "PPT 같다"

현재 `/intro`는 README의 섹션 구조(문제→설계 판단→화면→기술 선택→한계)를 그대로 블록으로 옮긴 것이다. 정보는 정확하지만 **읽는 문서지 보는 페이지가 아니다** — 표와 리스트가 이어지고 시각적 강약이 없다.

다시 설계할 때 지킬 원칙:

- **훅은 하나로 충분하다.** 지금처럼 히어로 아래 스크린샷 하나 + 지표 4칸이면 됐다. 문제는 그 아래부터 전부 같은 리듬(제목-표-리스트)이 반복되는 것이다.
- **스케일 대비를 쓴다.** 전부 13~15px 텍스트로 통일하지 말고, 한 섹션당 하나의 "큰 것"(인용구, 숫자, 이미지)을 두고 나머지는 그것을 뒷받침하게 배치한다. 06 스펙의 CTA 헤드라인 34px가 유일한 큰 순간인데, 중간에 하나도 없다.
- **표는 최후 수단이다.** "설계 판단" 7행 표는 정보 밀도는 높지만 페이지를 문서처럼 보이게 만드는 가장 큰 원인이다. 카드형 Before/After 비교나 좌우 분할처럼 시각적으로 다른 레이아웃을 섞는다.
- **여백을 늘린다.** 지금 섹션 간 패딩(64px)은 문서 기준으로는 넉넉하지만 랜딩 페이지 기준으로는 좁다.
- **문구는 field-experience.md 근거만.** 시각적으로 화려해지더라도 검증 안 된 주장을 만들지 않는다 — 이건 타협하지 않는다(0004 ADR).

## 8. 컴포넌트 패턴

| 패턴 | 함수/위치 | 비고 |
|---|---|---|
| 세그먼트 토글 | `seg(active, brand?)` (`lib/ui.ts`) | `brand=true`면 선택 상태가 브랜드색 |
| 프라이머리 버튼 | `primaryBtn` | 배경 `brand`, 글자 `onBrand` |
| 고스트 버튼 | `ghostBtn` | 배경 `surface`, 테두리 `line` |
| 상태 배지 | `pillStyle(status)` | 의미색, 다크 페어 없음(2절 참조) |
| 모노 라벨 | `monoLabel` | 섹션 소제목류 |

## 9. 알려진 갭 (이 문서 기준 시점)

- 소개 페이지 반응형 미구현 — 다음 과제.
- 상태·대비비·증감 배지 다크 페어 없음.
- 참가자 마이크로사이트의 실제 fluid 반응형(고정 프레임 밖) 미검증.
- 로고 CDN 폰트 의존(Pretendard) — FE-2에서 자체 호스팅 예정.
